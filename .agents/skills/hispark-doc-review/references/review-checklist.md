# Review 检查表

本检查表用于形成审查证据，不替代规范正文或项目批准流程。

## 1. 严重性

| 级别 | 判定 |
|---|---|
| P0 | 可能导致普遍性不可逆损害、严重安全泄露或发布整体不可用，必须立即阻断 |
| P1 | 会让默认路径、公开能力或关键技术事实明显错误，合入前必须修复 |
| P2 | 在常见条件下造成失败、误导、维护断裂或不符合明确要求，应在合入前修复 |
| P3 | 局部清晰度、可维护性或一致性问题，可排期处理 |

不要把个人风格偏好升级为问题。问题必须能从变更和证据中复现。

## 2. 必需 Reviewer

| 变更 | 最低角色覆盖 |
|---|---|
| 错字、标点或失效链接且不改含义 | 文档 Maintainer 或目录 Owner |
| 新页面、实质重写、类型变化、跨目录移动 | 文档 Maintainer + 领域 Owner |
| `get-started/`、Happy Path、首页、一级导航 | 文档 Maintainer + 领域 Owner；涉及运行路径时加验证 Reviewer |
| API、Kconfig、Target、构建、烧录、硬件、产品能力 | 领域 Owner + 文档 Maintainer；涉及运行声明时加验证 Reviewer |
| Sample 或测试覆盖变化 | Sample/领域 Owner + 测试/CI Owner + 文档 Maintainer |
| 上游版本、下游差异、临时副本、去重例外 | 文档 Maintainer + 领域 Owner |
| 安全、凭据、权限、不可逆操作 | 安全/风险领域 Owner + 领域 Owner + 文档 Maintainer |
| 发布候选、版本切换、大规模迁移、长期例外 | 发布 Owner + 文档 Maintainer + 受影响领域 Owner |

高风险变更至少需要两名独立批准人。作者不能批准自己的变更。实质修改影响技术含义、用户路径、风险、证据、上游版本或覆盖范围时，旧批准失效。

## 3. 内容与架构

- 页面只有一个主要用户意图，`doc_type` 与实际内容一致；
- 页面位于职责匹配的一级入口，跨类型内容通过链接拆分；
- `get-started/` 仍是唯一、受控、低认知负担的 Happy Path；
- Sample 页面是围绕真实任务的实践指南，并指向真实源码；
- 标题面向用户问题，不以内部模块或“介绍”“其他”代替；
- BCP 14 大写关键词只用于真正的规范性条款，偏离 `SHOULD` 的理由有记录；
- 非规范性解释块有明确标识，讨论实际问题、成因、机制和效果，并通过删除测试。

## 4. 产品和事实边界

- 产品、版本、Target、开发板/单板、配置和验证范围明确；
- 页面没有从同系列产品、相似代码或上游支持推断当前产品能力；
- 事实可追溯到当前源码、配置、发布物、测试或正式资料；
- 下游没有复制、翻译粘贴、近义改写或截图重建上游通用内容；
- `upstream_refs` 指向匹配版本和目标章节，下游差异明确；
- 页面状态、`last_verified` 和 `verification_level` 与证据一致。

## 5. 可执行性与风险

- 命令说明执行目录、环境和权限，并有关键预期结果；
- 占位符在首次出现时解释；
- 危险或不可逆操作的警告位于动作之前，说明影响和恢复边界；
- 失败分支提供可恢复入口；
- 静态核对、构建、Smoke 与 HIL 没有混用；
- 串口静默、超时、设备无响应、缺少成功标记或证据上传失败没有被判定为通过。

## 6. 图片与生成内容

- 图片传递文字难以等效表达的必要信息；
- 命令、日志、参数、配置和路径不是只存在于截图中；
- 关键结论有正文、图注或替代文本的等价表达；
- 图源可编辑并与导出产物映射，重复资产由单一来源维护；
- 截图标明必要版本/状态，不含凭据、内部地址、个人数据或设备唯一标识；
- 自动生成内容的事实源、生成器和最终渲染均已审查。

## 7. 合入判定

存在任一项时请求修改：事实无来源、适用版本不明、复制上游内容、默认路径不可复现、证据与声明不匹配、无 Owner、危险动作无恢复说明、必需门禁被跳过、阻塞评论未解决。

Review 记录至少保留 Reviewer、角色、结论、提交 SHA、关键证据链接、阻塞意见及处置。没有获得这些真实记录时，只能给出审查建议，不能声称“已批准”。
