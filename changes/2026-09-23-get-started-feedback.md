## 没有重复或放宽的部分

- 上游优先与下游差异继续由第 7.1—7.2 节定义；环境准备只增加进入/返回和预算边界，不复制安装百科。
- Static/Build/Smoke/HIL 仍以原领域与 Sample 模型为基础；Get Started 八阶段是执行记录，不另造可替代证据的等级体系。
- PR/Daily 继续使用相同实现，独立 Review、Owner、过期处理及原有发布阻断保持有效。
- 不再把固定页面/步骤/前置数量当作通用预算。替换为必须批准的逐叶数值上限，缺预算直接记缺口，既有更严格预算继续有效；禁止单为消除发现调高上限。
- 首次成功前零可选分支和建议 30 分钟目标保留；数字化目标与例外审批更明确。没有用户测试证据，不虚构已验证用时。
- 正式例外不删除发现、不伪造通过、不豁免报告完整性或失败传播。参考检查器更保守，不实现例外放行。
- Core 仍按原清单排除第 2.2 节及解释层；本次新增正文在两种 profile 中保留。新增手册与原写作模板一样是非规范性参考资料，不属于可选局部解释块。

## 配套交付与边界

- `docs/handbook/verification-and-adoption.md`：逐叶、矩阵、证据、采用/例外、迁移、构建闭包及部署清单；可选实现与操作提示。
- `examples/contracts/`：采用记录骨架、合成逐叶预算、必需检查计划和故意失败的历史发现报告。
- `scripts/validate_contracts.py`：工具无关数据的可选 Python 参考消费者；`scripts/test_contracts.py`：正向与故障注入测试，接入 `npm run check`。
- 仓库本地 Skills：仅同步与新正文冲突的导航、预算、状态及门禁摘要；未同步个人目录或其他采用项目。

参考检查器不检查真实网络归档、批准身份、用户测试真实性、SDK、硬件或采用项目的构建闭包。矩阵检查通过只表示其声明的必需阶段及结构满足参考检查；返回各阶段状态，不把可选未运行项提升为通过。事实源到 SDK Runner 的平台集成测试清单由手册提供，本仓库未冒充执行该试点。
