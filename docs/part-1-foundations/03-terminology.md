## 3.1 Diátaxis 术语

| 英文 | 标准中文 | 禁止或不推荐的混用 |
|---|---|---|
| Tutorial | 教程 | 与“实践指南”“示例”互换使用 |
| How-to guide | 实践指南 | 仅称“步骤说明”而不说明用户目标 |
| Reference | 参考资料 | 用“教程”包装接口清单 |
| Explanation | 解释说明 | 用“操作指南”承载长篇原理 |

## 3.2 HiSpark 技术术语

| 概念 | 标准写法 | 使用规则 |
|---|---|---|
| 品牌 | HiSpark | MUST 保持大小写，不写作 Hispark、HISpark |
| 产品 | 采用项目声明的正式产品名 | 页面 MUST 明列适用产品；MUST NOT 混入任何未声明产品的能力 |
| 软件开发包 | SDK | 首次出现 MAY 写作“软件开发包（SDK）”，后续统一使用 SDK |
| 应用程序接口 | API | 接口描述统一使用 API，不与 ABI 混用 |
| 操作系统抽象层 | OSAL | 首次出现写明 Operating System Abstraction Layer |
| 构建 | 构建 | 表示配置、编译、链接和打包的整体过程 |
| 编译 | 编译 | 仅表示源代码到目标文件等编译阶段 |
| 固件写入 | 烧录 | MUST NOT 使用含混的“下载”代替烧录 |
| 构建产物 | 产物 | 首次出现 SHOULD 明确 ELF、镜像或 `.fwpkg` |
| 示例源代码 | Sample / 示例 | 代码目录名保留 `sample`；中文正文优先使用“示例”或“参考案例” |
| 基于 Sample 的任务文档 | 实践指南 | `samples/` 页面 MUST 围绕可完成、可验证的开发任务组织，MUST NOT 仅因包含示例代码就称为教程 |
| 上游项目 | 上游 | 提供被集成软件、工具、协议或通用能力及其权威文档的来源项目；MUST NOT 泛指任意外部网站 |
| 下游项目 | 下游 | 集成、适配或发行上游能力的 HiSpark 产品项目；文档职责是表达集成入口和产品差异 |
| 上游引用 | `upstream_refs` | 记录上游项目、适用版本和稳定文档 URL，不等同于普通延伸阅读链接 |
| 首次成功路径 | Happy Path | `get-started/` 中经过端到端验证的唯一默认学习路径；MUST NOT 包含可选分支 |
| 每日文档持续集成 | Daily CI | 每日运行的全量文档健康检查；正文首次出现 SHOULD 写为“每日文档持续集成（Daily CI）” |
| 构建目标 | Target | 首次出现 SHOULD 同时给出采用项目中的实际值 |
| 开发板 | 开发板 | 用于开发与调试的板卡；MUST NOT 与量产单板、芯片混称 |
| 单板 | 单板 | 指具体板级硬件或被测对象时使用 |

英文缩写首次出现 SHOULD 使用“中文名（英文全称，缩写）”或“中文名（缩写）”。同一页面后续 MUST 使用同一写法。
