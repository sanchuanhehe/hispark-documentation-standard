---

## 3.1 Diátaxis 术语

| 英文 | 标准中文 | 禁止或不推荐的混用 |
|---|---|---|
| Tutorial | 教程 | 与“实践指南”“示例”互换使用 |
| How-to guide | 实践指南 | 仅称“步骤说明”而不说明用户目标 |
| Reference | 参考资料 | 用“教程”包装接口清单 |
| Explanation | 解释说明 | 用“操作指南”承载长篇原理 |

## 3.2 HiSpark 技术术语

| 概念 | 标准写法 | 使用规则 |
|---|---|---|
| 品牌 | HiSpark | 必须（MUST）保持大小写，不写作 Hispark、HISpark |
| 产品 | 采用项目声明的正式产品名 | 页面必须（MUST）明列适用产品；不得（MUST NOT）混入任何未声明产品的能力 |
| 软件开发包 | SDK | 首次出现可以（MAY）写作“软件开发包（SDK）”，后续统一使用 SDK |
| 应用程序接口 | API | 接口描述统一使用 API，不与 ABI 混用 |
| 操作系统抽象层 | OSAL | 首次出现写明 Operating System Abstraction Layer |
| 构建 | 构建 | 表示配置、编译、链接和打包的整体过程 |
| 编译 | 编译 | 仅表示源代码到目标文件等编译阶段 |
| 固件写入 | 烧录 | 不得（MUST NOT）使用含混的“下载”代替烧录 |
| 构建产物 | 产物 | 首次出现应当（SHOULD）明确 ELF、镜像或 `.fwpkg` |
| 示例源代码 | Sample / 示例 | 代码目录名保留 `sample`；中文正文优先使用“示例”或“参考案例” |
| 基于 Sample 的任务文档 | 实践指南 | `samples/` 页面必须（MUST）围绕可完成、可验证的开发任务组织，不得（MUST NOT）仅因包含示例代码就称为教程 |
| 上游项目 | 上游 | 提供本项目所集成的软件、工具、协议或通用能力及其权威文档的项目；不得（MUST NOT）泛指任意外部网站 |
| 下游项目 | 下游 | 集成、适配或发行上游能力的 HiSpark 产品项目；文档说明本产品如何接入、与上游有什么不同 |
| 上游引用 | `upstream_refs` | 记录上游项目、适用版本和稳定文档 URL，不等同于普通延伸阅读链接 |
| 首次成功路径 | Happy Path | 作者安排并从头到尾验证过的学习路径，首次成功目标和完成判据唯一，但可以包含多个页面；所选路径不得（MUST NOT）包含首次成功前的可选分支 |
| 入口决策 | Entry decision | 开始前为选择适用路径而回答的问题，各选项互斥；统计独立问题的数量，不统计同一选择控件出现了几次 |
| 叶子教程 | Leaf tutorial | 用户完成入口选择后，可以独立照着执行的一条单路径教程；预算与验证必须（MUST）能分别对每个叶子教程核算 |
| 平台展示变体 | Platform presentation variant | 各平台的目标、主要动作和完成判据相同，只是命令或环境说明不同；不得（MUST NOT）据此推断各平台已验证 |
| 首次成功后优化 | Post-success optimization | 不影响首次成功完成判据的可选性能、便利性或进阶配置；不得（MUST NOT）成为首次成功前置 |
| 导航页 | Navigation page | 只帮助用户选择入口和查找页面，不提供独立教学或任务流程；不是第五种 Diátaxis 内容类型 |
| 历史发现基线 | Finding baseline | 保存检查发现的历史记录，使用稳定标识与本次结果比较；`known` 为仍存在、`new` 为新增、`resolved` 为已消失；不得（MUST NOT）充当豁免清单 |
| 每日文档持续集成 | Daily CI | 每日运行的全量文档健康检查；正文首次出现应当（SHOULD）写为“每日文档持续集成（Daily CI）” |
| 构建目标 | Target | 首次出现应当（SHOULD）同时给出采用项目中的实际值 |
| 开发板 | 开发板 | 用于开发与调试的板卡；不得（MUST NOT）与量产单板、芯片混称 |
| 单板 | 单板 | 指具体板级硬件或被测对象时使用 |

英文缩写首次出现应当（SHOULD）使用“中文名（英文全称，缩写）”或“中文名（缩写）”。同一页面后续必须（MUST）使用同一写法。
