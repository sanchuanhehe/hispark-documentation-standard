**采用时如何安排工作**

本章是实施顺序，不设“降低要求后仍完全符合”的等级。先选一个真实页面试点，再补齐项目机制；每个阶段记录已满足、未满足和不适用项。现行条款规定的 Review、验证和发布门槛在适用场景中继续生效。

| 阶段 | 先交付什么 | 主要负责人 | 如何确认完成 |
|---|---|---|---|
| 建立基线 | 页面与来源清单、已知缺口 | 文档 Maintainer、领域 Owner | 范围、Owner、状态可追溯 |
| 试写与分类 | 一篇按模板完成的真实实践指南、清晰入口 | 作者、Reviewer | 本次变更清单及所需评审、验证通过 |
| 工程接入 | PR 门禁、Daily CI、Sample 映射和证据 | 测试/CI Owner、Sample Owner | 对照项目清单逐项给出结果 |
| 发布与推广 | 发布复核、例外与试点反馈 | 发布 Owner、项目负责人 | 对照适用发布条款核验，缺口显式披露 |

尚未完成的能力进入有 Owner、风险、下一步和复核日期的清单，例外按第 12.2 节记录。不得以“正在试点”为由把未验证内容提升为已验证。

## 13.1 阶段 1：建立基线

1. 以采用项目当前的一级目录和首页入口为基线建立清单。
2. 为所有内容页补充 `doc_type`、产品、版本、Owner 和验证级别。
3. 标记空页、占位页、不可运行样例、断链和跨产品污染。
4. 保留现有 URL，不在本阶段批量移动文件。

## 13.2 阶段 2：明确页面职责

1. 将快速入门收敛为唯一首次成功目标和完成判据，区分入口决策、叶子教程和平台展示变体。
2. 将环境搭建详解拆为可复用的实践指南或工具参考。
3. 将 `guides/` 中的架构解释和 API 清单分别链接到 `overall-architecture/`、`api-reference/`。
4. 将 `samples/` 统一整理为实践指南：每页围绕一个可完成、可验证的开发任务组织，并清理状态不明入口；学习型 Happy Path 迁移或链接至 `get-started/`。
5. 将 `FAQ/` 条目改为可搜索、可验证的问题解决页面。
6. 识别下游重复维护的上游内容，保留下游差异、适用范围和验证结果，将通用内容替换为版本匹配的 `upstream_refs`。
7. 收敛 `get-started/`，移出完整安装手册、参数百科、架构背景和可选方案，保留或直接链接最小环境准备，并按获批的逐叶预算消除首次成功前的认知障碍。

## 13.3 阶段 3：建立证据和门禁

1. 锁定文档构建依赖并建立可复现的严格构建。
2. 建立内部链接、锚点、图片替代文本和外链检查。
3. 为官方 Happy Path 建立构建与目标板 smoke/HIL 检查。
4. 建立 Sample 清单、源码、实践指南、Owner 和测试入口的双向映射。
5. 建立 Sample 构建、Smoke、HIL、负向和版本覆盖矩阵，并定义 PR、定期任务和发布门禁。
6. 为 API 和 Sample 建立源码漂移、测试过期和 Owner 失效检查。
7. docs-only PR MUST 进入上述门禁。
8. 配置使用同一检查实现的 Daily CI，覆盖全量构建、上游漂移、内容重复、`get-started/` 预算和验证有效期。
9. 为 Daily CI 配置告警、Owner、可跟踪回归项和发布阻断规则。

## 13.4 阶段 4：推广到 HiSpark 项目

1. 选择一个采用项目试点并记录例外。
2. 根据评审结果形成稳定模板与自动检查。
3. 在其他 HiSpark SDK 仓库中复用一级职责、四类页面和元数据模型。
4. 产品差异 MUST 通过适用范围和产品级内容表达，MUST NOT 复制任何未声明产品的事实或能力。

## 13.5 试行反馈怎么收集

选一名首次接触规范的作者，用[写作入口](../handbook/write-a-page.md)完成一篇真实 Sample 实践指南。记录以下观察，不预填改善结论：

- 找到模板及适用专项要求花了多久；
- 初稿用了多久，是否必须通读无关章节；
- 哪些字段、术语或证据要求需要口头解释；
- 首轮 Review 的问题属于事实、操作、证据还是格式；
- 作者能否区分页面变更检查和项目治理缺口。

据此优先修正入口、模板和重复表述；若需要改变约束强度，另列条款变化及影响供评审。不要用总页数下降替代采用效果。

## 13.6 工程接入与迁移记录

采用清单按[第 12.4 节](12-governance-and-maintenance.md)登记；历史债务按[第 10.5 节](../part-3-quality/10-review-and-merge.md)分类，不能通过重置基线消除阻断。页面删除、移动、重命名统一按[第 6.4.2 节](../part-2-authoring/06-authoring.md)检查旧入口及引用。

原子化提交、镜像创建、网络与认证排障属于工程操作，不属于内容规范。可选操作顺序和接入模板见[验证与接入手册](../handbook/verification-and-adoption.md)；实际仓库、平台、参数和权限由采用项目配置，不回写为通用要求。
