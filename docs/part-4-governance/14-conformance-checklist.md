---
title: '14. 符合性检查表'
---

## 14.1 信息架构

- [ ] 页面只有一个主要用户意图和一个 `doc_type`。
- [ ] 页面位于职责匹配的一级目录。
- [ ] 跨类型内容使用链接，而不是大段混写。
- [ ] `index.md` 提供清晰的角色或任务入口。
- [ ] 下游页面只保留产品差异和集成上下文，上游通用内容使用版本匹配链接。
- [ ] 没有通过复制、翻译后粘贴或近义改写重复维护上游内容。
- [ ] `get-started/` 只有一个默认 Happy Path，且符合页面、步骤、前置条件和分支预算。
- [ ] 新用户在首次成功前不需要理解未解释术语、内部架构或非必要选项。

## 14.2 Review 与批准

- [ ] 已根据变更类型请求全部必需 Reviewer，作者不是自己的批准人。
- [ ] Reviewer 的领域能力覆盖文档、技术、验证、安全和发布中的适用范围。
- [ ] Review 结论对应当前提交 SHA，实质变更后已重新请求批准。
- [ ] 所有阻塞意见已解决；未采纳建议有理由或可跟踪项。
- [ ] 事实来源、上游差异、验证证据和未验证边界已被实际审查。
- [ ] 自动生成内容同时审查了事实源、生成器和最终渲染结果。
- [ ] 例外具有风险、补偿措施、批准人和到期日期，没有作者自批例外。

## 14.3 技术事实

- [ ] 产品、版本、Target、路径、产物和工具名称准确。
- [ ] 代码和 API 声明可追溯到当前来源。
- [ ] 页面只声明适用范围内的能力，没有混入任何未声明产品、芯片或单板的事实。
- [ ] 静态核对、构建验证和 HIL 验证没有混淆。

## 14.4 可执行性

- [ ] 命令说明执行目录、环境和权限。
- [ ] 关键步骤有预期结果和完成判据。
- [ ] 危险操作在动作前给出风险和恢复说明。
- [ ] 示例有源码、配置、版本和状态。

## 14.5 质量

- [ ] 严格站点构建通过。
- [ ] 内链、锚点、图片和导航通过检查。
- [ ] 每张图片都有明确用途；可由文字、代码或表格稳定表达的内容没有被截图替代。
- [ ] 图片中的关键结论在正文、图注或替代文本中具有等价表达。
- [ ] 图片具有有效替代文本，装饰性图片可安全删除。
- [ ] 架构图、流程图和时序图保留可编辑源文件，并与导出产物建立映射。
- [ ] 截图标明必要的版本或界面状态，不包含无关区域、过期界面或敏感信息。
- [ ] 共享图片通过单一来源复用，没有产生独立维护的重复副本。
- [ ] 术语、大小写和文件命名符合规范。
- [ ] 页面 Owner、状态和验证日期完整。
- [ ] PR 文档门禁与 Daily CI 均已配置，且使用相同的可复现检查实现。
- [ ] Daily CI 在允许时间内成功运行；失败、阻塞和未运行没有继承旧的绿色状态。
- [ ] 上游链接、锚点、适用版本、内容漂移和疑似重复报告已复核。

## 14.6 维护与测试覆盖

- [ ] 每个支持范围内 Sample 都有稳定 `sample_id`、源码、实践指南、Owner 和测试入口。
- [ ] 源码与文档能够双向映射，不存在孤立页面或无文档 Sample。
- [ ] 代码、Kconfig、Target、API 和预期输出变更已同步更新页面与测试。
- [ ] 覆盖矩阵给出产品、版本、单板、角色、环境、分子、分母和统计日期。
- [ ] 构建、Smoke、HIL、负向和版本覆盖分别记录，没有用单一“通过”替代。
- [ ] 无响应、串口静默、超时和证据缺失按失败或阻塞处理。
- [ ] 未覆盖与阻塞项具有原因、风险、Owner、补测计划和复核日期。
- [ ] 发布候选的默认推荐 Sample 已达到项目规定的最低覆盖门槛。
